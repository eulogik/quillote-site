Help Support

How to get help.

Quillote is in public beta. Start here for requirements and the file model. If something is still stuck, write to us.

Updated 23 October 2026

Requirements

  • macOS: Universal build for Apple Silicon and Intel, macOS 10.13 or later. The current beta DMG is not signed or notarized.
  • iPhone: iOS 15 or later. The App Store build and TestFlight are the next step.
  • Android: Android 7.0 (API 24) or later. The signed APK is available on the download page; Play Store rollout is next.
  • Windows and Linux: CI-built installers are attached to the GitHub release. They are unsigned for now.

Opening the macOS beta

The beta is unsigned. Drag Quillote into Applications, then right-click the app and choose Open once. After that, macOS remembers it. If the app still refuses to launch, check System Settings → Privacy & Security for an Open Anyway button.

Installing on Windows

Run Quillote_0.1.0_x64-setup.exe (NSIS) or Quillote_0.1.0_x64_en-US.msi. The beta is unsigned, so SmartScreen will warn. Choose More info, then Run anyway. The MSI is the better choice for a managed or silent install; both install the same app.

Installing on Linux

The .deb and .rpm use the WebKitGTK that your distribution already ships, which is why they are under 3 MB. They are unsigned, so the package manager will warn about the missing repository signature. Use the command for your distribution:

# Debian, Ubuntu, Linux Mint, Pop!_OS
sudo apt install ./Quillote_0.1.0_amd64.deb

# Fedora, RHEL, CentOS Stream
sudo dnf install ./Quillote-0.1.0-1.x86_64.rpm

# openSUSE
sudo zypper install ./Quillote-0.1.0-1.x86_64.rpm

The AppImage is not shipped. Bundling WebKitGTK made it 82 MB, over the 10 MB installer budget. Flatpak and Snap are not in 0.1.0 either; they add a runtime and packaging maintenance that the first beta does not need. Arch users can try converting the .rpm with debtap, but that path is untested; a real AUR package waits for a real Arch test.

The phone file model

Phones do not hand apps a stable path they can write back to. Quillote copies a file you pick into its own sandbox, edits that copy, and exports through the share sheet. This is deliberate: it avoids the silent 0-byte writes that the content provider APIs can cause. Your original stays untouched until you export.

Known issues

  • The macOS DMG is unsigned in the public beta. Developer ID signing and notarization are the next step.
  • Windows and Linux installers are CI-built and unsigned. A native smoke test on each platform is still on the list.
  • The iPhone build is App Store-signed; TestFlight and App Store review are the next step.
  • On Android, the system picker ignores extension filters. Quillote checks the picked file name before it copies anything and refuses binary files.
  • Toggling word wrap or line numbers rebuilds the active view. The text and selection survive; the undo history for that document does not.

Something else?

Email hello@quillote.com with the app version, your platform, and the smallest file that reproduces the problem. If the file is private, describe the shape of it instead; do not send anything you would not want in an inbox.

You can also open an issue on the public site repository: github.com/eulogik/quillote-site/issues.
